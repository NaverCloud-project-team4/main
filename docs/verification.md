검증일: 2026-10-23. 로컬 FastAPI 두 프로세스(127.0.0.1:8000), 별도 검증 워커, React/Vite(127.0.0.1:5173), SQLite 및 로컬 파일 저장소를 사용했습니다.

## 결과

- Python 통합·어댑터 테스트 **21개 통과**.
- Ruff 정적 검사 통과.
- Vite 프로덕션 빌드 통과.
- 시스템 Chrome에서 브라우저 시나리오 **12개 통과**, 실제 HTTP 응답 **113건** 확인.
- 브라우저의 처리되지 않은 JavaScript 오류 0건, 브라우저 흐름 중 5xx 응답 0건.
- 1440px 데스크톱·390px 모바일 화면을 캡처해 확인했고, 모바일 가로 넘침이 없음을 확인했습니다.

## 브라우저에서 실행한 흐름

1. 프론트와 별도 포트의 API 연결·구역·피드 조회.
2. 화면에서 회원가입과 JWT 로그인.
3. 실제 multipart 사진 전송 → 202 접수 → 별도 워커 처리 → 상태 폴링 → 승인과 20P 적립.
4. 승인된 사진 피드 조회, 좋아요와 지역 집계 갱신.
5. 적립 포인트로 아이템 구매·장착.
6. 검토 시나리오의 사진이 공개 피드와 포인트에 반영되지 않음.
7. 운영자 로그인 후 검토 제보 승인.
8. 사용자 재로그인·페이지 새로고침 후 DB에 저장된 제보·잔액 확인.
9. 반려 시나리오의 사진 비공개와 포인트 미적립.
10. 모바일 화면과 브라우저/서버 오류 확인.

## 검증하지 않은 범위

NCP 실계정 배포, 관리형 MySQL 연결, 실제 Object Storage 이벤트 전달, Cloud Functions 런타임, CLOVA 실모델의 분류 정확도·요금·호출 제한은 아직 확인하지 않았습니다. Docker 데몬이 실행 중이지 않아 MySQL Compose도 실제로 구동하지 못했습니다. 부하 테스트를 통한 처리량 수치는 측정하지 않았습니다.

로컬 사진 검증은 사용자가 고른 테스트 결과를 재현합니다. 소나무·단풍 사진을 실제로 구분했다고 주장하는 검증 결과가 아닙니다. 키를 연결한 뒤 다양한 실제 사진으로 평가하고 자동 승인 기준을 조정해야 합니다.

## 지도·제보 화면 분리 후 확인

지도 화면과 사진 제보 화면이 별도로 열리는지, 지도에서 선택한 구역이 제보 화면에 유지되는지 확인했습니다. 로그인 후 왼쪽 위 프로필에서 본인 정보와 내 제보로 들어가고, 새 제보도 정상 제출되는 것을 브라우저에서 확인했습니다. 지도·사진 제보·프로필의 모바일 화면에서 가로 넘침이 없었습니다.

## 네이버 지도 전환 후 실제 연결 확인

로컬 지도 화면을 NCP Maps의 공식 JavaScript SDK로 교체했습니다. `kauroong` 애플리케이션에는 기존 localhost 설정과 별도로 실제 접속 호스트 `http://127.0.0.1`을 추가해 인증 실패를 해결했습니다. 실제 접속 주소는 `http://127.0.0.1:5173/`입니다.

인앱 브라우저에서 실제 네이버 지도 타일·NAVER 저작권 표시, DB 구역 5곳의 마커, 마커 클릭에 따른 구역 정보 변경, 선택 구역을 유지한 사진 제보 화면 이동, 지도 복귀와 전체 구역 보기, 키보드 Enter 선택을 직접 확인했습니다. 프로덕션 빌드도 통과했습니다. 지도 인증 실패 안내는 실제 허용 호스트가 맞지 않았던 상태에서 확인했습니다.

이 지도 전환 확인은 실제 인앱 브라우저의 UI로 수행했습니다. 위의 21개 백엔드 테스트 및 12개 기존 브라우저 시나리오 기록과 구분합니다. 화면 증거는 `artifacts/naver-map-connected.jpg`에 저장했습니다. `scripts/naver-map-smoke.cjs`는 SDK/타일과 오류 경로를 분리해 다시 실행할 수 있는 추가 검증 스크립트입니다.

## 현재 위치 기반 사진 제보

2026-10-23, 수동 구역 선택과 좌표 입력을 제거했습니다. 제보 화면 진입과 제출 직전에 브라우저 현재 위치를 요청하고, `POST /api/zones/resolve`로 안내할 구역을 확인합니다. 사진 제출은 `zone_id` 없이 실제 확인한 좌표를 보내며 서버가 해당 좌표를 포함하는 구역을 다시 계산합니다. 여러 범위가 겹치면 가장 가까운 중심을 가진 구역을 선택하고, 같은 거리는 ID로 결정합니다. 등록된 서비스 구역 밖이면 제보를 생성하지 않습니다. 위치 조회 자체는 DB에 저장하지 않습니다.

- Ruff 검사와 Vite 프로덕션 빌드 통과.
